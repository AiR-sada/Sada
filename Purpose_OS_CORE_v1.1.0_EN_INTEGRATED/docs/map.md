# docs/map.md — Purpose OS CORE の読み方

> **非規範（non-normative）**
>
> この文書は `spec.md` の読み方を助けるための導線です。正本の意味を変更しません。
> 矛盾がある場合は `spec.md` が優先します。

## これは何か

`spec.md` は Purpose OS の基盤モジュールである CORE を定義する仕様です。
この `docs/map.md` は、初見の読者が全体像を短時間で掴むための案内です。最初の入口は `START_HERE.md`、よくある質問は `FAQ.md`、AI・successor 向けの導線は `AI_README.md` にあります。

## なぜこの仕様が必要か

複数の知性が同じ世界に関わりながら、異なる現実を立て、異なる判断をし、異なる時間軸で行動します。人間、AI、将来の新たな知性。

ここで必要なのは、単発の正解や局所ルールではなく、**何に向かって判断し続けるか** の起点です。Purpose OS は、その起点を **Purpose** として定め、その上で世界の見方と目指し方の土台を置きます。

## この release が置くもの

この release は、CORE 単独で成立する最小公開単位として次を置きます。

- 起点: `Purpose` / `OS`
- 安全制約: Purposeを単一スコア最適化・報酬関数化・代理指標化・強制・犠牲化・高リスク自律実行の根拠にしないための原則
- 世界側の土台: `世界(W)` / `知性(Φ)` / `現実(i)` / `空間(S)` / `ΔS` / `領域(R)` / `ΔT` / `時空(R_t)`
- 運用側の土台: `aim`・`value`・`Vision`・`Goal`・`Task`・`現状`・`意思決定`・`実行`
- 定義の道具: `構造` / `定義` / `分岐`

## この release がまだ置かないもの

この release は、次をまだ置きません。

- 後続モジュールの具体内容
- 複数知性の `value` 衝突を一意に解消する規則
- 候補 `Task` の生成方法
- 同順位候補の一意解消規則
- 知性と非知性の境界基準
- Purpose の集計規則と時間重みづけ
- Purpose 自体を改訂する場合の具体的評価規準（提案形式は `release/ROOT_MAJOR_TEMPLATE.md` が補助）
- AI agent の自律実行、高リスク・不可逆・大規模実行の許可条件
- 既存哲学との関係の論証

したがって、この文書は Purpose OS 全体の最終完成形ではなく、**後続展開の基盤** です。ただし、Purposeの濫用を防ぐための最低限の安全制約はCOREに含まれます。CORE 単体は、高リスク行為や AI agent の自律実行を許可する実装仕様ではありません。

## 全体構成

### 1. 序 — Purposeの宣言

ここでは Purpose OS の起点を置きます。

- `Purpose OS`
- `Purpose` — 現在からより未来へ続く全知性および幸/不幸の主体たりうる存在について、避けうる深刻な不幸を減らし、より幸せでありうる条件を広げる方向
- `Purposeの安全制約` — 補助表現「深刻不幸低減・幸福条件拡張」を単一スコア最適化・幸/不幸の算術的最大化/最小化命令・報酬関数化・代理指標化・強制・犠牲化として誤読しないための原則
- `OS` — Purpose に向かうための基盤
- `幸/不幸` — 知性および幸/不幸の主体たりうる存在にとっての望ましさと望ましくなさの総合
- `より未来` — 現在を含み、あらゆる時点のさらにその先へ開く

最初にここを読むと、この仕様が何に向かうかが分かります。

### 2. CORE 第1部 — 世界と現実

知性が立つ「場」の構造を定義します。

主な軸:

- `世界(W)` — ありのまま
- `知性(Φ)` — 世界を受け取り、評価し、世界または自己の状態に差を生じさせうるもの
- `現実(i)` — 世界に対して知性 i に成立する全体
- `空間(S)` / `ΔS → 領域(R)` / `+ΔT → 時空(R_t)`
- 現実(i) の内容: `事象` / `真理`
- 現実(i) の形式: `SV` / `v`

この部は、「何の上で判断が行われるか」を定めます。

### 3. CORE 第2部 — Purposeの目指し方

第1部で定義された場の上で、Purpose に向かう運用を定義します。

主な流れ:

- `Purpose : aim / value`
- `aim → Vision`
- `Vision ; 現状 → Goal`
- `Goal ; 現状 → Task`
- `Task ; 現状 ⇒ 意思決定 → 実行`
- `現状 : 自 / 他`

aim は方向を、value は許容・禁止の基準を与えます。Vision → Goal → Task の系列で目指す状態を段階的に具体化し、意思決定が候補 Task から採用対象を定め、実行が世界への作用を行います。実行の結果は、次の意思決定時点の現状に含まれうる。第2部に共通する制約として、Vision・Goal・Task・意思決定・実行は aim に沿い、value に反してはなりません。この制約は依存関係ではなく、上記の成立関係および運用の流れを変更・追加しません。重大な意思決定では、不確実性・不可逆性・理由記録も問題になります。

### 4. 参照部 — 定義の道具

仕様全体で使う「定義の道具」を置きます。

- `構造`
- `定義`
- `分岐`
- `閉じた分岐`
- `開いた分岐`

## 三層の見方

- **マクロ**: 構造を見る
- **メソ**: 本質を見る
- **ミクロ**: 完全定義を見る

解釈で迷う場合は、`spec.md` の規定どおり **ミクロ → メソ → マクロ** の順で優先します。

## 概念IDの使い方

ミクロの概念は、`序-2` や `①-8` のような概念IDで参照できます。
引用や議論では、概念名だけでなく概念IDも併記するとずれにくくなります。

例:

- `序-2 Purpose`
- `①-8 現実(i)`
- `②-9 意思決定`
- `②-10 実行`
- `参-1 構造`

## 誤読しやすい点

- `世界(W)` と `現実(i)` は同じではありません。世界は「ありのまま」、現実(i)は「知性 i に成立する全体」です。
- `Purpose` は単一スコアの最大化関数ではありません。方向を示すrootです。報酬関数・代理指標でもありません。
- `深刻不幸低減・幸福条件拡張` は補助表現・短縮表現であり、幸/不幸を単一尺度で計算して最大化・最小化する命令ではありません。
- `真理` は世界の構造そのものではなく、知性が構造について成立させる表現です。
- `文型` と `例` は理解補助であり、定義・Not・制約・依存を追加・変更・限定しません。
- `依存構造の概観（非規範）` は要約であり、完全な依存関係は各ミクロの `依存` 行を参照します。
- `docs/map.md` は読み方ガイドであって、正本の外側から意味を追加する文書ではありません。
- CORE 単体は、高リスク行為や AI agent の自律実行を許可する実装仕様ではありません。
- ΔT と時空の記述は、物理学上の時間・空間理論を置換するものではありません。
- この仕様は特定の既存哲学文献への依存関係をここでは定義しません。思想史上の比較や解説は、必要なら別の非規範文書の役割です。
