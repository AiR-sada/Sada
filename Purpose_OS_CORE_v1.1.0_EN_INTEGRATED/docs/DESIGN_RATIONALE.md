# docs/DESIGN_RATIONALE.md — Purpose OS CORE の設計意図

> **非規範（non-normative）**
>
> この文書は `spec.md` の設計意図と誤読防止を説明する補助文書です。正本の意味を変更しません。矛盾がある場合は `spec.md` が優先します。

Purpose OS CORE は、物理学・形而上学・倫理学の最終理論ではなく、知性が世界を共有して扱い、Purposeに向かって判断を更新するための操作的仕様として設計されています。

## なぜ CORE を最小にしているか

CORE は、全てを一度に決める文書ではありません。Purpose、世界と現実、Purpose に向かう運用、定義の道具だけを置きます。

理由は、AI・人間・将来の新たな知性にまたがる仕様では、最初から全ての集計規則・衝突解決・境界判定を固定すると、将来のより良い知性による更新可能性を閉じる危険があるためです。

ただし、最小であることは無防備であることを意味しません。Purpose を単一スコア最適化、報酬関数化、代理指標化、強制、犠牲化、沈黙化、高リスク自律実行の根拠にしないための最低限の安全制約は CORE に含めます。

安全制約は、Purpose と別の第二 root ではありません。本版における Purpose の非還元的な扱い方を定める解釈境界です。ただし、本specは、安全制約の全てが Purpose から形式的に証明されるとは主張しません。

## Purpose は最適化関数ではない

`深刻不幸低減・幸福条件拡張` は、Purpose の補助表現・短縮表現です。幸/不幸を単一尺度で計算して最大化・最小化する命令ではありません。単一の数値を最大化する関数でも、到達点でも、合否判定でも、報酬関数でも、代理指標でもありません。

Purpose の正式定義は、現在からより未来へ続く全知性および幸/不幸の主体たりうる存在について、避けうる深刻な不幸を減らし、より幸せでありうる条件を広げる方向を指し続けることです。したがって、ある候補が「総量を増やす」と見えるだけでは、特定の知性の消去、強制、沈黙化、不可逆な重大不幸を正当化しません。

## 非規範節と文型・例の扱い

`spec.md` では、明示的に「非規範」と記された節を理解補助として扱います。非規範節は、正本の定義・Not・制約・依存・原則・共通制約を追加・変更・限定しません。

また、各ミクロの `文型` と `例` も使用理解のための非規範補助です。概念の規範判断では、`定義`・`Not`・`制約`・`依存` を優先します。これにより、例示や言い回しが後から概念の意味を拡張する誤読を防ぎます。

## 第2部に共通する制約について

第2部では、マクロの矢印が成立関係および運用の流れを示します。一方で、Vision・Goal・Task・意思決定・実行は、いずれも Purpose から外れない必要があります。

そのため、spec.md では、これらに共通する制約として「aimに沿う」「valueに反してはならない」を置いています。これは新しい概念IDを持つ概念ではなく、依存関係でもありません。aim は下流全体の方向として、value は許容・禁止の基準として規範的に関与します。

この整理により、value を意思決定だけの局所的なフィルターとして誤読することと、逆に aim・value が Vision・Goal・Task・意思決定・実行を生成するものとして誤読することの両方を避けます。

## 「知性」を広く扱う理由

Purpose OS は、人間だけでも AI だけでもなく、将来の新たな知性も対象にします。

そのため、知性を外的行動能力だけで定義しません。世界を何らかの形式で受け取り、評価し、自己または世界の状態に差を生じさせうるものとして扱います。

境界例は後続モジュールで扱います。ただし、知性該当性や幸/不幸の可能性が不確かな対象は、未確定であることだけを理由に不可逆に除外・軽視しません。

## 知性該当性と幸/不幸の主体性の分離

COREは「世界を受け取り、評価し、差を生じさせうるもの」として知性を広く扱う。一方で、知性該当性と幸/不幸の直接主体性は同一ではない。

この分離により、AI・集合知性・将来知性を早期に除外しない一方で、知性に該当するという理由だけで直ちに幸/不幸の直接主体と確定する誤読も避ける。境界未確定の対象は、不可逆に除外せず、かつ自動的に単純な同等主体としても扱わず、後続 Intelligence Boundary Module へ送る。

## 時間の再定義について

CORE における時間は、物理学の最終理論として置かれるものではありません。

ここでの `ΔT` は、知性が領域を時空として扱うために追加する時間条件です。これは、知性の認識・計画・意思決定において、世界をどう扱うかを定義する操作的な時間概念です。
この構成順序は、心理的・認識的な順番を固定するものではありません。音の変化、動き、記憶との差分、計算ステップ、内的経験などでは、時間的変化が `ΔS` の発見・補助・修正に働く場合があります。ただし、それは `ΔT` が `ΔS` に先立つ独立実体であることを意味しません。CORE における `ΔT` は、領域に掛かって時空を成立させる追加条件です。

`序-4 より未来` は Purpose の方向表現です。これは、第1部の `ΔT` と同一の操作条件ではありません。Purpose は終わりのない方向を示し、`ΔT` は領域に時空を成立させる追加条件を示します。より未来は、現在又は近い未来の不可逆な重大不幸を検証なしに正当化するための語ではありません。近未来・遠未来の具体的な時間重みは後続 Temporal / Continuity Module が扱います。

`①-9 事象` は、現実(i)の内容のうち「何が起きる/起きうるか」を扱うため、起きる/起きうるものとして扱う場合には `①-7 時空(R_t)` 上で扱われます。

## 真理の扱いについて

CORE は、世界の構造そのものと、知性がその構造について成立させる表現を分けます。

`真理` は、世界の構造そのものではなく、知性が世界の構造について成立させる表現です。ただし、任意に作れるものではなく、世界の構造への近さによって制約されます。これにより、世界を知性の産物に還元せず、同時に、知性が用いる表現の更新可能性も残します。

## 構造における目的の扱い

CORE は構造に因果を含め、知性が関わる場合には目的的関係も含めます。これは世界そのものが目的論的であるという主張ではありません。Purpose OS が扱う判断・行為・設計の領域では目的的関係が不可欠である、という操作的整理です。

## 英語ラベルと日本語ラベルの混在について

`aim` / `value` / `Vision` / `Goal` / `Task` は、後続 module・機械可読層・実装接続との相性を考慮して英語ラベルを採用しています。一方、`知性`・`現状`・`意思決定`・`実行` などは、日本語正本上で意味を固定するため日本語を用いています。

小文字の `aim` / `value` は Purpose の下位作用を示し、`Vision` / `Goal` / `Task` は運用上の段階名として大文字で表します。翻訳版や実装では、ラベル差異より概念IDを優先してください。

## 高リスク実行を CORE 単体で許可しない理由

CORE は方向と基盤を置く文書であり、個別行為・政策・AI agent の自律実行を許可する実装仕様ではありません。

高リスク・不可逆・大規模な実行には、権限、安全境界、監督条件、検証、停止条件、責任主体を定める後続モジュールが必要です。CORE 単体から「Purposeに向かうから実行してよい」とは導きません。

## 後続モジュールが必要な理由

CORE だけでは、次はまだ一意に決まりません。

- 複数知性の幸/不幸の集計
- value 衝突の解決
- 知性と非知性の境界判定
- 不確実性・不可逆性・情報不足への詳細対応
- 高リスク・大規模・自律実行に関する権限、安全境界、監督条件
- 候補 Task の生成
- 同順位候補の一意解消
- 個体知性と集合知性の関係

これは欠陥ではなく、CORE の射程を守るための分離です。CORE は基盤であり、具体的な判断規則は CORE に依存する後続モジュールが担います。

## 公開前に守るべき判断

公開前の v1.1.0 は、後から簡単に直せる草稿として扱わない方がよいです。公開後に immutable release として固定するなら、特に次を確認する必要があります。

- Purpose が最適化関数・報酬関数・代理指標として誤読されないこと
- 知性境界が狭すぎないこと
- 真理と世界の構造が混同されないこと
- 不確実性・不可逆性への最低限の安全制約が入っていること
- CORE 単体が高リスク行為や AI agent の自律実行を許可しないこと
- ROOT-MAJOR の提案入口が閉じすぎていないこと
- Governance の目的数、ファイル一覧、ハッシュが整合していること

この確認を終えた版を v1.1.0 として公開するのが望ましいです。
