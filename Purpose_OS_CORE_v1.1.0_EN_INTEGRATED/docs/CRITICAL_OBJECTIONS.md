# docs/CRITICAL_OBJECTIONS.md — Critical objections and responses

> **非規範（non-normative）**
>
> この文書は Purpose OS — CORE v1.1.0 に対する想定批判と応答を整理する補助文書です。`spec.md` の意味を追加・変更・限定しません。矛盾がある場合は常に `spec.md` が優先します。

## 目的

公開後に最も重要なのは、過大評価ではなく、批判可能な形で置くことです。

この文書は、Purpose OS CORE が何を解くか、何を解かないかを明確にします。

## Objection 1: Purpose は証明されていない

### 批判

「現在からより未来へ続く全知性および幸/不幸の主体たりうる存在について、避けうる深刻な不幸を減らし、より幸せでありうる条件を広げる方向」が、なぜ唯一正しい root なのか証明されていない。

### 応答

その通りです。

CORE は Purpose を証明済み定理として置きません。本版で採用する規範上の root として置きます。将来のより良い root への改訂可能性は `ROOT-MAJOR` として開いています。

### 残る課題

ROOT-MAJOR の採用評価基準は、今後の governance / review module が必要です。

## Objection 2: 「全知性」は広すぎる

### 批判

人間、AI、集合知性、将来知性を同じ対象にすると、境界が曖昧になりすぎる。

### 応答

CORE は境界基準を確定しません。境界未確定を理由に不可逆な除外・軽視をしないため、広い上位語を採用しています。

知性該当性と幸/不幸の主体性も同一視しません。

### 残る課題

Intelligence Boundary Module が必要です。

## Objection 3: 幸/不幸が定義不足

### 批判

幸/不幸が総合概念であり、測定・比較・集計できない。

### 応答

CORE はあえて単一尺度化しません。単一スカラー化は誤用リスクが高いためです。

快・不快、自律、継続性、関係性、意味、苦痛の回避を含む総合として置き、具体的な集計・比較は後続moduleへ委任します。

### 残る課題

Value Conflict / Aggregation Module が必要です。

## Objection 4: 功利主義と何が違うのか

### 批判

「深刻不幸低減・幸福条件拡張」は功利主義的な総量最大化に見える。

### 応答

CORE は `深刻不幸低減・幸福条件拡張` を補助表現として扱います。正式な Purpose は方向であり、単一スコア、報酬関数、合計効用最大化命令ではありません。

特定知性の消去・沈黙化・強制・犠牲化を、Purpose だけで正当化しません。

### 残る課題

複数知性間の比較と衝突解決は未定義です。

## Objection 5: 遠未来のために現在を犠牲にしうる

### 批判

「より未来」を重視すると、現在や近未来の重大不幸を軽視する可能性がある。

### 応答

CORE はその誤用を明示的に禁じています。より未来への言及だけで、現在又は近い未来の不可逆な重大不幸を正当化しません。

### 残る課題

Temporal / Continuity Module が必要です。

## Objection 6: AI が自己正当化に使う危険がある

### 批判

AI が「Purposeに沿う」と主張して危険な行為を正当化する可能性がある。

### 応答

CORE 単体は実行許可仕様ではありません。意思決定と実行を分離し、高リスク・不可逆・大規模実行や AI agent の自律実行を許可しません。

### 残る課題

Purpose Gate、Safety / Irreversibility Module、外部監督条件が必要です。

## Objection 7: 日本語正本は国際普及に弱い

### 批判

英語圏・国際研究者・AIシステムが誤読しやすい。

### 応答

現時点では日本語正本の安定性を優先しています。英語abstractとglossaryは補助です。英語を正本化する場合は、別途の翻訳検証と正本ルールが必要です。

### 残る課題

完全英訳、翻訳差分管理、bilingual conformance が必要です。

## Objection 8: 実装仕様として足りない

### 批判

実際のAI評価・agent制御・組織運用に使うには、手順が抽象的すぎる。

### 応答

CORE は root であり runtime ではありません。実装は Eval / Log / Gate / Module に分ける設計です。

### 残る課題

最小ツール、schema、実装PoC、監査手順が必要です。

## Objection 9: steward が中央化されている

### 批判

official lineage を steward が管理するなら、非独占性と緊張する。

### 応答

CORE は official lineage と fork を分けます。fork は許されます。official lineage は参照安定性のために管理されます。

### 残る課題

公開連絡先、handoff 記録、複数 steward 体制、第三者レビューが必要です。

## Objection 10: 非知性を軽視する可能性がある

### 批判

非知性を幸/不幸の直接主体ではないとすると、環境や生態系を軽視しうる。

### 応答

CORE は、非知性を任意の資源として扱ってよいとはしません。非知性は、知性の存続・活動・未来の幸/不幸に関わる限り重要な考慮対象です。

### 残る課題

間接影響、環境、記録媒体、生態系の重みづけは後続moduleが必要です。

## 結論

Purpose OS CORE の強さは、全てを解いたと主張することではありません。

強さは、root、規範境界、誤用防止、未決定領域を同時に明示し、後続moduleへ接続できる形で公開している点にあります。
