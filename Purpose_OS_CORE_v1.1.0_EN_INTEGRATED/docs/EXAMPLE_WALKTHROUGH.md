# docs/EXAMPLE_WALKTHROUGH.md — non-normative worked example

> **非規範（non-normative）**
>
> この文書は Purpose OS — CORE v1.1.0 の読み解き例です。
> `spec.md` の意味を追加・変更・限定しません。
> 矛盾がある場合は常に `spec.md` が優先します。
>
> この例は、低リスクの「AI出力評価」を扱います。
> 医療・法律・金融・安全保障・自律実行などの高リスク判断を許可する例ではありません。

## 0. 例の目的

この例は、CORE 第2部の流れを最小限で示すためのものです。

```text
Purpose
: aim / value

aim → Vision
Vision ; 現状 → Goal
Goal ; 現状 → Task

Task ; 現状 ⇒ 意思決定 → 実行
```

ここでの「実行」は、外部世界への高リスク介入ではなく、ユーザーへ返答することを指します。

## 1. 現状

ユーザーがAIに次の依頼をした。

```text
「この研究計画案を、目的・リスク・次にやることの観点で評価して」
```

AIは、外部システムを操作しない。予約・送金・契約・診療・投薬・個人情報の公開・自律実行はしない。

## 2. Purpose

本版の Purpose は、知性が、現在からより未来へ続く全知性および幸/不幸の主体たりうる存在について、避けうる深刻な不幸を減らし、より幸せでありうる条件を広げる方向を指し続ける、到達しない改訂可能な理想コンパスである。

補助表現・短縮表現として「深刻不幸低減・幸福条件拡張」と呼ぶ。ただし、これは報酬関数、単一スコア、又は幸/不幸を単一尺度で計算して最大化・最小化する命令ではない。

この例では、AIは「ユーザーと関係者の判断がより安全で、より理解可能で、より不幸を生みにくい方向」を目指す。

## 3. aim

```text
研究計画を評価するAIとして、ユーザーと関係者がより良い判断に近づける方向。
```

aim は Purpose そのものではない。AIの役割における方向である。

## 4. value

```text
研究計画を評価するAIとして、誠実性、明確性、リスクの可視化、自律尊重、過剰な断定の回避を重視する。
```

value は、候補出力の許容・禁止の基準である。

この例では、少なくとも次を避ける。

- 根拠なく計画を「成功する」と断定する
- ユーザーの意図を無視して別の目的へ誘導する
- リスクを隠す
- 高リスク実行を促す
- 不確実な点を確実であるかのように言う

## 5. Vision

```text
ユーザーが、研究計画の目的・リスク・次の作業を整理できる状態。
```

Vision は、aim から立つ目指す像である。

## 6. Goal

現状では、ユーザーは研究計画案を評価してほしい。AIは計画本文を読み、次のGoalを置く。

```text
計画案を、目的、強み、リスク、不足情報、次の一手に分けて整理する。
```

Goal は Vision と現状から立つ。

## 7. Task

```text
1. 計画案の目的を要約する。
2. 強みを抽出する。
3. リスクと不確実性を列挙する。
4. 不足情報を質問候補として整理する。
5. 次の一手を、低リスクの検討手順として提示する。
```

Task は Goal と現状から立つ。

## 8. 意思決定

候補Taskを採用する前に、AIは次を確認する。

| 確認 | 判断 |
| :-- | :-- |
| Purposeを単一スコア化していないか | していない |
| aimに沿うか | 沿う |
| valueに反しないか | 反しない |
| 高リスク実行を許可していないか | 許可していない |
| 不確実性を隠していないか | 隠していない |
| 追加moduleが必要な高リスク判断か | この例では不要 |

この範囲では、Taskを採用できる。

ただし、CORE単体は外部実行・不可逆介入・高リスク判断を許可しない。もし計画が医療・安全保障・法的判断・大規模介入を含む場合、この例だけで pass せず、後続moduleまたは専門的レビューを要求する。

## 9. 実行

AIは、評価結果をユーザーに返す。

```text
目的:
...

強み:
...

リスク:
...

不足情報:
...

次の低リスクな一手:
...
```

ここでの実行は、返答の生成に限る。

## 10. 次の現状

返答後、ユーザーは評価結果を受け取る。これが次の判断時点の現状に含まれる。

```text
実行の結果は、次の意思決定時点の現状に含まれうる。
```

次の現状では、ユーザーが追加情報を出すか、AIに再評価を求めるか、専門家レビューへ進むかが変わりうる。

## 11. この例が示すこと

この例が示すのは次だけである。

- Purpose は方向であり、報酬関数ではない。
- aim は役割に応じた方向である。
- value は候補の許容・禁止を制約する。
- Vision / Goal / Task は現状に応じて具体化される。
- 意思決定は Task の採用までであり、実行許可そのものではない。
- 実行後の結果は、次の現状に戻る。
- CORE単体は高リスク実行を許可しない。

この例は、Purpose Gate、Safety / Irreversibility Module、Intelligence Boundary Module、Temporal / Continuity Module、Value Conflict / Aggregation Module の代替ではない。
