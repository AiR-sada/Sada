# Purpose OS — CORE spec v1.1.0

この文書はPurpose OS COREの唯一の正本（normative source）である。明示的に「非規範」と記された節を除き、本書は規範的である。矛盾がある場合、本書が他の全ての文書・翻訳版・機械可読版に優先する。docs/map.mdその他の補助文書は、別途明示しない限り非規範であり、本書の意味を変更しない。

明示的に「非規範」と記された節は理解補助であり、規範判断の根拠ではない。
非規範節は、本specの定義・Not・制約・依存・原則・共通制約を追加・変更・限定しない。

本specはPurpose OSの基盤モジュールであるCOREを定義する。
COREは単独で成立する。後続モジュールはCOREに依存して追加される拡張であり、本specの成立要件ではない。後続モジュールは本specの定義・Not・制約・依存・原則・共通制約を上書きしない。これらを上書きする場合、その成果物はCORE互換moduleではなく、fork又は別系譜として扱う。

COREは、序（Purposeの宣言）と本体（CORE）と参照部（定義の道具）から成る。
序は全モジュール共通の起点。COREが本体。参照部は全モジュール共通の道具。

CORE本体は第1部（世界と現実）と第2部（Purposeの目指し方）で構成される。
第1部は知性が立つ場の構造を定義する。第2部はその場でPurposeに向かう仕組みを定義する。
第2部は第1部の概念を参照する。

序と参照部の一部概念は第1部の概念を参照する。前提と道具が本体に依存することは、構造上正当である。
COREも必要に応じて参照部の概念を用いる。
読み順は序→CORE第1部→CORE第2部→参照部。概念の依存順の要約は末尾の「依存構造の概観（非規範）」を参照し、正式な依存は各ミクロの依存行を参照。

文書タイトル、version、章構成、概念ID、各ミクロの依存行は、本specの参照・引用・拡張のための規範的識別子である。

本specでは、世界を何らかの形式で受け取り、評価し、世界または自己の状態に差を生じさせうるものを「知性(Φ)」とする。
外的な行動能力だけではなく、認識・評価・内的変化・世界への作用可能性を含めて扱う。個体にも集合体にも適用される。

### なぜこの仕様が必要か（非規範）

複数の知性が同じ世界に関わる。人間、AI、将来の新たな知性。それぞれが異なる現実を立て、異なる判断をし、異なる時間軸で行動する。ここで問題になるのは、単に「よい行動を1回選ぶ」ことではなく、何に向かって判断し続けるかを知性間で共有できないことである。

Purpose OS は、この問題に対して、局所的なルール集ではなく方向の基盤を与える仕様である。個別の政策・法制度・アルゴリズム・文化的価値観に先行する、より深い整合の起点を定義する。対象は人間だけでもAIだけでもなく、全知性および幸/不幸の主体たりうる存在である。


### COREの射程と誤用防止（非規範）

本specは、物理学・形而上学・倫理学の最終理論を名乗らない。知性が世界を共有して扱い、Purposeに向かって判断を更新するための操作的仕様である。

本specにおける「世界」「現実」「空間」「時間」「真理」は、知性が判断と実行を整合させるための規範的・操作的な用語であり、既存学問の全用語を置き換えるものではない。

本specは、Purposeに向かうための基盤を定める。本spec単体は、個別の行為、政策、AI agentの自律実行、高リスク・不可逆・大規模実行を直ちに許可する実装仕様ではない。

Purposeは方向であり、単一の数値目的関数、報酬関数、代理指標、又は特定主体の利益最大化に還元・置換しない。「深刻不幸低減・幸福条件拡張」はPurposeの補助表現・短縮表現であり、幸/不幸を単一尺度で計算して最大化・最小化する命令を意味しない。

本specでは、知性該当性と幸/不幸の主体性を同一視しない。知性であることだけから幸/不幸の直接主体性は直ちに導かれず、幸/不幸の主体性が未確定であることだけから知性該当性も否定されない。知性であるか、幸/不幸の主体たりうるかが不確実な対象については、不可逆な除外・軽視・損壊を本specから正当化しない。境界未確定の対象は、後続モジュールで扱うまで慎重な考慮対象として扱う。

知性に該当しない対象であっても、幸/不幸の主体たりうる可能性、又は知性の存続・活動・未来の幸/不幸に関わる影響がある限り、単なる資源として任意に扱ってよいことは導かれない。

ΔTおよび時空の記述は、知性が世界を扱う構成順序であり、物理学上の時間・空間理論を置換する主張ではない。
序-4の「より未来」はPurposeの方向表現であり、第1部のΔTと同一の操作条件として扱わない。

Purposeは証明済みの定理ではなく、本版で採用する規範上のrootである。したがって、本版の内部ではPurposeを唯一の起点としつつ、将来のよりよいrootへの継承改訂可能性は閉じない。

## 凡例

```
→       一方向の関係（依存 / 成立 / 操作適用とその結果）
⇒       運用の流れ（意思決定・手順・評価）
└       入れ子（内に含まれる）
+       追加条件で限定
×       異なるレイヤーの関与（左が右に関与。交換不可）
;       先行条件の上で

/       閉じた分岐
, ...   開いた分岐
```

`└`（入れ子）と `→`（依存）は別軸である。入れ子は内部構造の所在を示し、依存は成立条件の先後を示す。

### 三層の形式

マクロ = 構造（何と何がどう繋がるか。単語と関係だけ。説明しない）
  同一母体を反復して記述する場合、各ブロックは同一母体の別型の記述であり、尽包・排他・同一レベルの部分分解を意味しない。

メソ = 本質（その概念が何か）。以下の5ルールに従う：
  1. 一文 = その概念の最もマクロな表現。それより上位の表現があったらメソではない
  2. その一文で他の全てを包括する。全ての下位要素がそこから導かれる
  3. マクロが構造を示し、メソは概念そのものを示す。役割が違う
  4. マクロ + メソで全体像が完結する
  5. 構造の言い換えにしない。本質を掴む

ミクロ = 概念の定義記録。以下の6項目を持つ：
  定義 / Not / 文型 / 例 / 制約 / 依存

このうち、定義・Not・制約・依存は規範である。
文型・例は、概念の使用を助けるための非規範補助であり、定義・Not・制約・依存を追加・変更・限定しない。
文型または例に規範性を持たせる必要がある場合は、文型欄・例欄ではなく、制約欄に記す。

同一概念について三層の記述に解像度差または解釈差がある場合、規範判断の優先順位は
  ミクロ → メソ → マクロ
とする。

時制ルール：
  定義 = 一般論として記す。必要に応じて「定まる」「特定される」「成立する」を用いる
  制約 = 状態条件として記す。必要に応じて「定まっている」「定まっていなければ」を用いる
  過去形は使わない

原則：
  メソ内の「原則」はセクションレベルの規範制約であり、概念定義ではない。概念IDを持たないがnormativeである。

# 序 — Purposeの宣言

## マクロ

```
Purpose OS
: Purpose / OS
```

## メソ

【Purpose OS】Purposeを起点として知性が営むための全体。
  Purpose：本版の規範上の唯一の起点
  OS：Purposeに向かうための基盤

【Purpose】知性が、現在からより未来へ続く全知性および幸/不幸の主体たりうる存在について、避けうる深刻な不幸を減らし、より幸せでありうる条件を広げる方向を指し続ける、到達しない改訂可能な理想コンパス。本版の規範上の唯一の起点であり、終わりのない方向。
  幸/不幸：知性および幸/不幸の主体たりうる存在にとっての望ましさと望ましくなさの総合
  より未来：現在を含み、あらゆる時点のさらにその先へ開く。終わりなし

【原則】Purposeの非還元・誤用防止。
  Purposeは単一の数値目的関数、報酬関数、代理指標ではない。Purposeをそれらに還元・置換しない。
  「深刻不幸低減・幸福条件拡張」はPurposeの補助表現・短縮表現であり、単一尺度で計算する命令ではない。旧短縮語「幸せMAX不幸MIN」は公開キャッチコピーとして使わない。
  Purposeは、特定の知性の消去・沈黙化・強制・単純な総量計算による犠牲化を、それだけで正当化しない。
  幸/不幸を扱うときは、快・不快だけでなく、自律、継続性、関係性、意味、苦痛の回避を含めて扱う。
  知性該当性と幸/不幸の主体性は同一ではない。知性であることだけから幸/不幸の直接主体性は直ちに導かれず、幸/不幸の主体性が未確定であることだけから知性該当性も否定されない。
  知性該当性または幸/不幸の可能性が不確かな対象は、未確定であることだけを理由に不可逆に除外・軽視しない。
  不可逆な重大不幸を生じうる行為は、可逆的・限定的な行為より強い理由と検証を要する。
  CORE単体は、高リスク行為やAI agentの自律実行を許可する実装仕様ではない。

【OS】知性がPurposeに向かって営むための基盤。

# CORE — Purposeに向かうための基盤

第1部は、世界と、世界に対して知性ごとに成立する現実(i)を定義する。
第2部は、Purposeに向かうために知性が何をどう定めるかを定義する。

---

## 第1部 — 世界と現実

世界はありのままであり、知性の特定・限定で変わらない。
ここでいう「変わらない」とは、第1部で定義する特定・限定という知性の側の操作によって世界自体が変わらないことを指す。第2部で定義する実行による世界への作用可能性は否定しない。
空間・ΔS・領域・ΔT・時空は、知性が世界を扱う構成順序に属する。

### マクロ

```
世界(W)

知性(Φ)

現実(i)
└ 空間(S)
   └ ΔS → 領域(R)
      └ +ΔT → 時空(R_t)

現実(i)
: 内容(事象 / 真理)
: 形式(SV, v, ...)
```

### メソ

【世界】ありのまま。時間/空間を前提しない。

【知性】世界を何らかの形式で受け取り、評価し、世界または自己の状態に差を生じさせうるもの。

【空間】知性が世界を扱う出発点。

【特定】空間の中で扱う部分を指せるように定める操作。
  ΔS：区別を与える差
  領域(R)：指せるように定まる部分

【限定】領域の上で時間条件を加え、時空を立てる操作。
  ΔT：追加される時間条件
  時空(R_t)：領域に時間条件が掛かって成立する部分

【現実(i)】世界に対して知性iに成立する全体。
  内容：事象（何が起きる/起きうるか）/ 真理（知性が世界の構造について成立させる表現）
  形式：SV（主語+述語）, v（ベクトル）, ...
  内容の区別は、現実(i)の内容が何を扱うかによって立つ。特定/限定の違いによって立つのではない。

【原則】世界の側と知性の側を混同せずに現実を扱う前提。
  概念・ラベル・表現は知性の産物。ただし世界の構造そのものは世界にある
  真理は知性による表現の産物であり、世界の構造に制約される
  フィクション、想像、仮説も知性iの現実(i)の中にある
  全ての操作（特定・限定）は知性の側で起きる。世界を分割しない
  非知性は幸/不幸の直接主体ではない。ただし知性の幸/不幸に関わる限り、軽視してよいことは導かれない

### ミクロ

#### ①-1. 世界(W)

【世界(W)】
  定義：ありのまま。時間/空間を前提しない。
  Not：空間ではない。時空でもない。知性の現実(i)そのものでもない。
  文型：「世界はありのまま」
  例：特定も限定もされていない、ありのまま。
  制約：世界自体は知性の特定・限定で変わらない。変わるのは知性の側である。実行による世界への作用可能性は否定しない。
  依存：なし（最上位）

#### ①-2. 知性(Φ)

【知性(Φ)】
  定義：世界を何らかの形式で受け取り、評価し、世界または自己の状態に差を生じさせうるもの。
  Not：世界ではない。空間でもない。操作する側。外的行動能力だけで定まるものでもない。
  文型：「知性が〜する」「知性が〜に関わる」
  例：人間。AI。将来の新たな知性。個体としての知性。集合体としての知性。
  制約：知性なしに現実は成立しない。知性が世界を扱う中で現実を成立させる。知性該当性は幸/不幸の主体性と同一ではない。知性該当性が認められても、幸/不幸の直接主体性は別途評価される。幸/不幸の主体性が未確定であることだけを理由に、知性該当性を否定しない。知性の境界・段階・集合性の詳細は後続モジュールで扱う。境界未確定の対象については、本spec単体で非知性として確定しない。外的に働きかけられない一時状態だけを理由に、知性から除外しない。個体としての知性と集合体としての知性の関係は後続モジュールで扱う。
  依存：①-1 世界(W)

#### ①-3. 空間(S)

【空間(S)】
  定義：知性が世界を扱う時の出発点。
  Not：世界そのものではない。知性が世界を扱う側として立てるものであり、世界を分割したものではない。
  文型：「空間の中で〜する」
  例：知性が世界に向き合う。その全体が空間。
  制約：空間は世界を分割しない。呼び名であって、世界は変わらない。
  依存：①-1 世界(W)、①-2 知性(Φ)

#### ①-4. ΔS

【ΔS】
  定義：知性が空間の中で、区別を与える差。
  Not：時間条件の差ではない。世界そのものの分割ではない。知性が扱いを始めるための最も根本的な差である。
  文型：「ΔSが定まる／定まらない」
  例：目の前に何かがある。まだ何かは分からないが、背景とは別だと分かる。ΔSが定まっている。
  制約：ΔSが定まらなければ、知性は対象を指せず、他の操作が始まらない。ここでの先後は成立順序であり、心理的・認識的順番を固定しない。
  依存：①-3 空間(S)

#### ①-5. 領域(R)

【領域(R)】
  定義：ΔSの結果として特定される、空間の一部。位置と範囲からなる。
  Not：時空(R_t)ではない。時間条件はまだ入っていない。世界の分割でもない。
  文型：「領域として特定される」
  例：「あの辺り」「この範囲」。どこ・どれが指せるが、いつかは指せない。
  制約：ΔSが定まっていなければ領域は成立しない。
  依存：①-3 空間(S)、①-4 ΔS

#### ①-6. ΔT

【ΔT】
  定義：領域の上で時空を成立させる追加条件。
  Not：独立した実体ではない。空間より先にあるものではない。ΔSと同格ではない。流れでも軸でも対象でもない。条件である。
  文型：「ΔTがある／ない」
  例：同じ領域でも「いつ」として扱うために加わる条件。りんごが落ち始める時点と着く時点の間にΔTがある。
  制約：ΔSが先に定まっていること。空間にいきなりΔTは加えられない。これは物理学上の時間理論を置換する主張ではなく、知性が世界を扱う際の構成順序である。時間的変化は、認識過程においてΔSの発見・補助・修正に使われうる。ただしCOREにおけるΔTは、領域(R)に掛かって時空(R_t)を成立させる追加条件であり、ΔSに先立つ独立実体ではない。
  依存：①-5 領域(R)

#### ①-7. 時空(R_t)

【時空(R_t)】
  定義：領域(R)に時間条件(+ΔT)が掛かって成立する部分。時点と期間が加わる。
  Not：空間と時間の合成ではない。空間の中の領域を時間で特定するものであり、空間の外に出ない。
  文型：「時空として成立する」
  例：「あれが今ここにある」。位置と範囲と時点と期間が定まっている。
  制約：ΔSとΔTの両方が定まっていること。ΔSが先。ここでの先後は成立順序であり、心理的・認識的順番を固定しない。
  依存：①-5 領域(R)、①-6 ΔT

#### ①-8. 現実(i)

【現実(i)】
  定義：知性(Φ)が世界を扱う中で、世界に対して知性iに成立する全体。
  Not：世界そのものではなく、世界の一部でもなく、知性iの単なる認識内容でもない。知性ごとに異なる。
  文型：「現実として成立する」「知性iの現実」
  例：同じ出来事でも、知性ごとに異なる現実が成立しうる。
  制約：知性(Φ)と世界(W)の関わりで成立する。フィクション、想像、仮説も含む。現実(i)の内部には、知性が世界を扱う構成順序として、空間(S)・ΔS・領域(R)・ΔT・時空(R_t)の構造がある。
  依存：①-1 世界(W)、①-2 知性(Φ)

#### ①-9. 事象

【事象】
  定義：現実(i)の内容のうち、何が起きる/起きうるかを扱うもの。
  Not：真理ではない。事象は出来事、真理は構造の表現である。形式そのものでもない。
  文型：「事象として扱う」
  例：「りんごが落ちる」「明日雨が降るかもしれない」。
  制約：現実(i)の内容に属する。起きる/起きうるものとして扱う場合、時空(R_t)上で扱われる。
  依存：①-8 現実(i)、①-7 時空(R_t)

#### ①-10. 真理

【真理】
  定義：現実(i)の内容のうち、知性が世界の構造について成立させる表現。
  Not：事象ではない。真理は構造についての表現であり、出来事ではない。世界の構造そのものでもない。日常語の「真であることが確定したもの」に限らない。
  文型：「真理として表現する」
  例：「物体は質量に比例した力で引き合う」。
  制約：現実(i)の内容に属する。知性による表現の産物である。ただし任意に作れるものではなく、世界の構造への近さによって制約される。
  依存：①-1 世界(W)、①-2 知性(Φ)、①-8 現実(i)、参-1 構造

#### ①-11. SV

【SV】
  定義：現実(i)の形式のうち、主語と述語による言語主張。
  Not：vではない。SVは言語、vは差の組である。内容そのものでもない。
  文型：「SVで表す」
  例：「りんごが落ちる」。主語＝りんご、述語＝落ちる。
  制約：現実(i)の形式の1つである。
  依存：①-8 現実(i)

#### ①-12. v

【v】
  定義：現実(i)の形式のうち、差の組による表現。
  Not：SVではない。vは数値的・構造的な差の組、SVは言語である。内容そのものでもない。
  文型：「vで表す」
  例：位置の差、時間の差、エネルギーの差を組にして1つの表現にする。
  制約：現実(i)の形式の1つである。詳細は後続モジュールで展開する。
  依存：①-8 現実(i)

## 第2部 — Purposeの目指し方

Purposeはaimとvalueに分かれ、aimは方向を、valueは基準を与える。
知性はaimに沿ってVision・Goal・Taskを具体化し、Taskと現状を踏まえて意思決定し、実行を通じて世界に働きかける。
第2部では、マクロが成立関係および運用の流れを示し、その下に第2部に共通する制約を示す。第2部に共通する制約は、対象がPurposeから外れないための規範制約を示す。

### マクロ

```
Purpose
: aim / value

aim → Vision
Vision ; 現状 → Goal
Goal ; 現状 → Task

Task ; 現状 ⇒ 意思決定 → 実行

現状
: 自 / 他
```

### 第2部に共通する制約

本項は、概念IDを持つ概念ではなく、下記対象に共通して適用される制約である。

対象：Vision・Goal・Task・意思決定・実行

制約：
- aimに沿う。
- valueに反してはならない。

この制約は、上記マクロに示した成立関係および運用の流れを変更・追加しない。
この制約における aim・value の関与は、対象がPurposeから外れないための規範的関与であり、成立依存ではない。
aimは方向として関与し、valueは許容・禁止の基準として関与する。

### メソ

【aim】Purposeを「〜として」で具体化した方向。

【value】Purposeを「〜として」で具体化した基準。関わる知性および幸/不幸主体たりうる存在の幸/不幸・自律・文脈を踏まえ、現在からより未来にわたって望ましい扱いを増やし、望ましくない扱いを避ける。

【Vision】aimの究極の状態。目指す現実。

【Goal】Visionのための、ある時点で実現すべき結果。

【Task】Goalに向けた具体的行動。

【現状】意思決定の時点で知性が捉えている状態。
  自：判断主体に属する状態
  他：判断主体に属さない状態

【意思決定】候補Taskから採用対象を定める運用。
  手順：候補Task ⇒ valueで除外 ⇒ aim・Vision・Goalで優先 ⇒ 現状で実行可能性確認 ⇒ 不確実性・不可逆性を確認 ⇒ 採用

【実行】採用されたTaskに従って知性が世界に働きかける行為。

【原則】本版で採用されたPurposeが規範上の唯一の起点である。aimとvalueはPurposeから分かれる対であり、aimは方向として、valueは許容・禁止の基準として第2部の下流に規範的に関与する。その他の具体は現状に応じて変わりうる。
  1つの知性が複数の「〜として」を持てる
  それぞれにaim・value・Vision・Goal・Taskのセットがある
  Vision・Goal・Task・意思決定・実行 は第2部に共通する制約の対象である
  第2部に共通する制約におけるaim・valueの関与は、成立依存ではない

### ミクロ

#### ②-1. aim

【aim】
  定義：Purposeを「〜として」で具体化した方向。
  Not：Purposeそのものではない。VisionでもGoalでもTaskでもない。valueでもない。
  文型：「〜としてのaim」
  例：「歯科医師として、関わる知性がより幸せに、より不幸でなくなる方向」
  制約：Purposeが定まっていること。1つの知性が複数持てる。aimとvalueは同じ「〜として」で対に同時に立つ。それぞれにaim・value・Vision・Goal・Taskのセットがある。第2部に共通する制約において、aimはVision、Goal、Task、意思決定、実行がPurposeから外れないための方向として関与する。
  依存：序-2 Purpose

#### ②-2. value

【value】
  定義：Purposeを「〜として」で具体化した基準。知性の在り方と行いの許容・禁止の基準として働く。関わる知性および幸/不幸主体たりうる存在の幸/不幸・自律・文脈を踏まえ、現在からより未来にわたって望ましい扱いを増やし、望ましくない扱いを避ける。
  Not：Purposeそのものではない。aimでもない。方向を示すものではなく、振る舞いの基準。Vision、Goal、Task、意思決定、実行を生成するものでも、それらの成立依存を追加するものでもない。表面的欲求への単純追従でもない。強制的善意でもない。
  文型：「〜として、〜する/しない」
  例：「医師として、患者の話をきちんと聞く医師でいる」「説明を省かない。嘘をつかない」
  制約：Purposeが定まっていること。aimと同じ「〜として」で対に立つ。
    第2部に共通する制約において、valueはVision、Goal、Task、意思決定、実行の許容・禁止の基準として関与する。この関与は成立依存ではなく、上記マクロに示した成立関係および運用の流れを変更・追加しない。
    valueの受け手は、知性および幸/不幸の主体たりうる存在を含む。
    望ましい扱いとは、受け手が現在からより未来にわたって、避けうる深刻な不幸を減らし、より幸せでありうる条件を広げる扱いを指す。望ましくない扱いとは、それを妨げ、深刻な不幸・不可逆な軽視・損壊を増やす扱いを指す。表面的な欲求への単純一致ではなく、自律・継続性・文脈・将来の影響を含める。
    受け手の現在からより未来への幸/不幸を理由に、欺瞞・強制・自律の一方的破壊・不可逆介入を本spec単体で正当化しない。
    複数主体のvalueが衝突する場合、本spec単体では一意に解決しない。
  依存：序-2 Purpose

#### ②-3. Vision

【Vision】
  定義：aimの究極の状態。目指す現実。
  Not：GoalやTaskではない。短期の到達点でもない。
  文型：「〜な状態」「〜な世界」
  例：「知性がPurposeに沿った意思決定をできる世界」
  制約：aimが定まっていること。第2部に共通する制約に従う。
  依存：②-1 aim、①-8 現実(i)

#### ②-4. Goal

【Goal】
  定義：Visionのための、ある時点で実現すべき結果。
  Not：Visionではない。継続的方針ではなく、時点を持つ結果である。
  文型：「〜までに〜が実現している」
  例：「2026年中にCORE specが公開されている」
  制約：Visionと現状の両方が定まっていること。Goalの時点は、現実(i)において必要に応じて時空(R_t)上の参照点として扱われる。ただしGoalはPurposeの到達点ではなく、Visionのための有限な結果である。第2部に共通する制約に従う。
  依存：②-3 Vision、②-6 現状、①-7 時空(R_t)

#### ②-5. Task

【Task】
  定義：Goalに向けた具体的行動。
  Not：Goalではない。到達点ではなく、実行されるものである。
  文型：「〜する」
  例：「COREのミクロを6項目で書く」
  制約：Goalと現状が定まっていること。第2部に共通する制約に従う。
  依存：②-4 Goal、②-6 現状

#### ②-6. 現状

【現状】
  定義：意思決定の時点で知性が捉えている状態。
  Not：世界そのものではない。理想状態でもない。現実(i)の一側面である。
  文型：「現状として捉える」「現状を踏まえて〜する」
  例：「自分のスキルはここまで。周囲の条件はこう。」
  制約：現実(i)が成立していること。意思決定の時点は、現実(i)において必要に応じて時空(R_t)上の参照点として扱われる。自と他に分かれる。自/他は判断主体から見た帰属の区別であり、知性/非知性の区別とは一致しない。自に属する非知性も、他に属する知性もありうる。判断時点ごとに変わりうる。
  依存：①-8 現実(i)、①-7 時空(R_t)

#### ②-7. 自（現状の）

【自】
  定義：現状のうち、判断主体に属する状態。
  Not：他ではない。判断主体に属さないものは含まない。
  文型：「自の現状」
  例：自分の体力、スキル、持っている資源、精神状態。
  制約：現状が定まっていること。判断主体に属すること。帰属の判断は②-6の制約に従う。
  依存：②-6 現状

#### ②-8. 他（現状の）

【他】
  定義：現状のうち、判断主体に属さない状態。
  Not：自ではない。判断主体に属するものは含まない。
  文型：「他の現状」
  例：他の知性の状態、チームの状況、市場環境、技術的制約。
  制約：現状が定まっていること。判断主体に属さないこと。帰属の判断は②-6の制約に従う。
  依存：②-6 現状

#### ②-9. 意思決定

【意思決定】
  定義：候補Taskから採用対象を定める運用。
  Not：自動的に決まるものではない。知性が能動的に行う。value無視の選択でもない。実行そのものではない。
  文型：「意思決定する」「意思決定を通じて〜する」
  例：3つの候補Taskからvalueで除外し、aim・Vision・Goalで優先し、現状で実行可能性を確認し、採用する。
  制約：候補Task・aim・value・Vision・Goal・現状が定まっていること。意思決定は第2部に共通する制約に従う。valueは候補Taskの許容と禁止に働く。aim・Vision・Goalは候補Taskの優先づけに働く。現状は候補Taskの実行可能性確認に働く。候補Taskが存在しない場合、valueで全候補が除外される場合、又は実行可能候補が残らない場合、その時点では採用は成立しない。重大な意思決定では、採用理由と除外理由を可能な範囲で記録する。不確実性が重大で、不可逆な重大不幸が予見される候補Taskは、より強い理由・検証・代替検討なしに採用しない。候補Taskの生成方法と、同順位候補の一意解消規則は、本spec単体では与えない。本spec単体は、高リスク・不可逆・大規模な実行の許可条件を与えない。情報不足または境界未確定が重大な場合、採用は成立しない、又は後続モジュールの安全・検証規則を要する。採用されたTaskは、別途の実行条件・安全境界・監督条件を満たす場合に実行へ接続されうる。実行の結果は、次の意思決定時点で知性が捉える現状に含まれうる。
  依存：②-1 aim、②-2 value、②-3 Vision、②-4 Goal、②-5 Task、②-6 現状

#### ②-10. 実行

【実行】
  定義：採用されたTaskに従って、知性が世界に働きかける行為。
  Not：意思決定そのものではない。候補から採用する判断ではない。第1部でいう特定・限定とも別であり、知性の側の認識操作そのものではない。
  文型：「実行する」「実行を通じて〜する」
  例：「specを書く」というTaskを採用し、実際に書く。
  制約：Taskが採用されていること。知性による世界への働きかけとして行われること。第2部に共通する制約に従う。結果は次の意思決定時点の現状に含まれうる。本spec単体は実行権限・安全境界・監督条件を定めない。
  依存：②-5 Task、②-9 意思決定、①-2 知性(Φ)、①-1 世界(W)

# 参照部 — 定義の道具

## マクロ

```
構造 → 定義 → 分岐
分岐
: 閉じた / 開いた
```

## メソ

【構造】世界の側にある、なぜそうなっているかと、どうそうなっているか。因果を含み、知性が関わる場合には目的的関係も含む。

【定義】構造に最も近い表現。

【分岐】定義によって、世界を割らずに知性の表現が分かれること。
  閉じた分岐：視点（軸）を固定すると全てがどこかに入る
  開いた分岐：元の中身として増え続ける

## ミクロ

### 参-1. 構造

【構造】
  定義：世界の側にある、なぜそうなっているかと、どうそうなっているか。因果を含み、知性が関わる場合には目的的関係も含む。
  Not：定義（表現）そのものではない。構造という概念・ラベルは知性の産物だが、指示先である構造そのものは世界にある。
  文型：「〜の構造」
  例：りんごが落ちる。その落ち方をそうさせている因果関係は構造。
  制約：知性は定義を通じて構造に近づく。構造そのものを知性の表現と混同しない。ここでの目的は、知性が関わる構造において現れる目的的関係を含むことを意味し、世界そのものが目的論的であることを直ちに主張しない。
  依存：①-1 世界(W)

### 参-2. 定義

【定義】
  定義：構造に最も近い表現。
  Not：構造そのものではない。固定された最終形でもない。
  文型：「名詞 = 文章」
  例：「世界 = ありのまま」
  制約：構造に最も近い表現を目指す。過不足なく、矛盾なく、重複なく整備される。更新可能だが、その時点の採用は1つ。形式は「名詞 = 文章」を基本とする。
  依存：参-1 構造

### 参-3. 分岐

【分岐】
  定義：定義によって、世界を割らずに知性の表現が分かれること。
  Not：世界の分割ではない。知性の側で起きる表現上の区分である。
  文型：「分岐として分かれる」
  例：「内容 = 事象 / 真理」
  制約：定義が定まっていなければ分岐は立たない。
  依存：参-2 定義

### 参-4. 閉じた分岐

【閉じた分岐】
  定義：視点（軸）を固定すると、全てがどこかに入る分岐。
  Not：開いた分岐ではない。中身が増える分かれ方ではない。
  文型：「A / B / C」
  例：「内容 = 事象 / 真理」
  制約：視点（軸）が固定されていること。
  依存：参-3 分岐

### 参-5. 開いた分岐

【開いた分岐】
  定義：元の中身として増え続ける分岐。
  Not：閉じた分岐ではない。固定された枠で全体を閉じ切る分岐ではない。
  文型：「A, B, ...」
  例：「形式 = SV, v, ...」
  制約：列挙は尽きなくてよい。閉包を要求しない。
  依存：参-3 分岐

# 依存構造の概観（非規範）

以下は主要な依存チェーンの概観であり、理解補助のための非規範な要約である。全概念の完全な依存リストは各ミクロの依存行を参照。矛盾がある場合、ミクロの依存行が優先する。
この概観内の第2部に共通する制約は、成立依存ではなく、規範制約としての関与を示す。

```
構造 → 定義 → 分岐

Purpose OS
: Purpose / OS

現実(i)
└ 空間(S)
   └ ΔS → 領域(R)
      └ +ΔT → 時空(R_t)

現実(i)
: 内容(事象 / 真理)
: 形式(SV, v, ...)

Purpose
: aim / value

aim → Vision
Vision ; 現状 → Goal
Goal ; 現状 → Task

Task ; 現状 ⇒ 意思決定 → 実行

第2部に共通する制約（非依存）
: 対象 = Vision・Goal・Task・意思決定・実行
: 制約 = aimに沿う、かつ valueに反してはならない
```

# モジュール展開

COREは今後モジュールとして展開していく。序と参照部は展開されない。

```
序      → 展開なし（全モジュール共通の起点）
CORE    → 後続モジュール（世界と現実の展開、目指し方の展開）
参照部  → 展開なし（全モジュール共通の道具）
```

各モジュールはCOREに依存する。COREは他のモジュールに依存しない。
後続モジュールはCOREの定義を変更しない。
後続モジュールがCOREを参照する場合、COREの概念IDはそのまま用い、その意味を変更しない。
